## BBU 场景质检 — 场景描述与项目概览

### 背景与目标
- **目标**: 在通信机房 BBU 场景下，基于多张图片（工单级）判定是否满足安装与质量要求，输出“通过/不通过+简要原因”。
- **两段式能力**:
  - **Stage‑A（逐图）**: 每张图生成一行中文摘要（无坐标/无特殊标记）。
  - **Stage‑B（整组）**: 汇总多图摘要，给出工单级结论与简要理由。
- **端到端导向**: 以工单级监督为主，尽量减少硬编码规则，允许模型学习“规则之外”的证据整合与协同判断。

### 数据要素与对象空间
- **对象类型（6）**: `bbu`, `bbu_shield`, `connect_point`, `label`, `fiber`, `wire`。
- **几何约束**:
  - `fiber|wire → line`；其余 `bbox_2d|quad`。
- **描述字符串（desc）规范**（严格层次、定序与分隔）：
  - **逗号**分同级，**斜杠**分层级；条件属性按位出现；末级可为少量自由文本（remarks）。
  - 训练与推理以统一模板构建会话；偏差会触发严格校验与早失败。
- **覆盖性提醒**：
  - 标签：仅在无法识别时在摘要中输出`标签/无法识别`；可读时不输出标签内容。
  - 挡风板需求与符合性：若摘要出现“无需安装”，则不再要求输出“按要求配备/未按要求配备”。

### 两阶段流程（SFT → 工单级推理/RL）
- **SFT（`src_new/`）**
  - HF‑first 管线，严格校验图文/跨度/几何不变量；可选坐标 token 模式与分组损失（caption/grounding/formatting）。
  - 小比例引入“逐图一行摘要（summary）”变体，降低与 RL 阶段的分布漂移。
- **工单级推理与（可选）RL（`src_post/`）**
  - Stage‑A: 一行中文摘要/图；
  - Stage‑B: 文本聚合出“通过/不通过+原因”。
  - 可选 GRPO：仅用工单级标签作为奖励，实现端到端对齐；优先更新 Stage‑A，Stage‑B 可冻结或小步更新。

### 工单级判定的特殊性（难点）
- **主观性与噪声**: 相同现象可能因“特殊情况（角度/遮挡/整改/空间限制）”导致不同结论。
- **跨图矛盾**: 不同图像对同一属性给出“已配备/未配备”“正确/错误”等相反证据，需要组内协同整合。
- **证据稀疏与不确定**: 单图可见信息有限，要求模型在“不确定”时采用谨慎表述，避免误导组判定。

### 端到端训练策略（仅工单级监督优先，弱风格约束）
- **组级奖励**: 使用 Stage‑B 对“正确结论”的对数似然/概率差作为**连续化 margin 奖励**（替代纯 0/1）。
- **信用分配（无需硬规则）**：
  - **单图反事实差分**: 固定其它摘要，仅替换第 i 张摘要，优势 `Δ_i = margin(S_-i, s'_i) − margin(S)`，用于更新该摘要生成（低方差、直观可解释）。
  - **成对反事实（可选、少量）**: 当所有单图 `Δ_i≈0` 且组仍错时，抽 1–2 对图片联合替换，估计交互效应，将优势平均分摊以覆盖“AND/互补证据”场景。
- **塑形项（风格而非规则）**：
  - **cleanliness/formatting**: 一行中文、无坐标/无 `<|...|>`、无方括号、去重复。
  - **coverage**: 基于 `MISSION_CHECKS_COVERAGE` 的规范短语计算覆盖度（mission‑aware）；当摘要含“无需安装”时自动满足“挡风板符合性”；taxonomy 与 coverage 联动过滤。
  - **excuse tax**: “无法判断/已整改/角度问题/遮挡严重”等谨慎表述仅在提升组级 margin 时净收益为正，防止滥用。
  - **KL 到参考**: 以 SFT checkpoint 为参考，小权重 KL 约束稳定风格、防投机。
- **更新策略**: Stage‑A 为主，Stage‑B 可冻结或小步交替更新（强 KL）。
- **解码约束**: 训练与推理一致屏蔽几何/坐标 token；低温或贪心+少量采样（K=2–3）。

### 推理与协同行为（无硬编码规则）
- **Stage‑A**: 
  - 仅输出一行中文；无法确认时“如实模糊表述”；优先覆盖关键信息；不使用坐标/特殊标记。
- **Stage‑B**: 
  - 从多行摘要中学习“证据加权与一致性偏好”：具体明确的摘要优于含糊表述；冲突时更可信的证据影响更大。
  - 输出严格两行模板：
    - 通过：`总评: 通过`
    - 不通过：两行（`总评: 不通过` + `原因: <关键依据>`）

### 关键不变量与健康检查（训练/推理一致）
- **图文对齐**: `<|image_pad|>` 数与 `sum_i (t_i*h_i*w_i) // (merge_size^2)` 一致；`pixel_values` 行数等于 `sum_i (t_i*h_i*w_i)`。
- **跨度/标签**: 助手跨度包含紧随 `<|im_end|>`；span 外全部 `-100`；offset‑mapping 严格对齐。
- **坐标模式（可选）**: `<|coord_*|>` 连续区间及 128 对齐检查；几何特殊 token 存在性校验。

### 与“规则引擎”的关系
- **不依赖硬规则**: 端到端 RL 以组级奖励为主导，让模型学习超出清单的表达与证据组合。
- **可选基线**: 规则引擎可作为上线前的保底与可解释对照，不进入训练信号。

### 运行指引（最小骨架）
- **环境**: `conda activate ms`（或 `/root/miniconda3/envs/ms/bin/python`）。
- **SFT 训练**:
```bash
/root/miniconda3/envs/ms/bin/python scripts/train_new.py --config /abs/config.yaml --log_level INFO
```
- **推理（训练匹配，多图）**:
```bash
/root/miniconda3/envs/ms/bin/python -m src_new.inference \
  --config_path /abs/config.yaml \
  --model_path /abs/ckpt_best \
  --data_root /abs/data/ds_v2_full \
  --dataset val \
  --output_file /abs/out.jsonl \
  --num_teachers 0 --max_new_tokens 512 --temperature 1e-6
```
